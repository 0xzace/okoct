# OKOCT Health V0.1 设计说明

状态：依据用户提供的项目初始化规格进入实现；未进行生产发布授权。

## 目标与意图

OKOCT Health 是面向泰国市场的独立、非商业健康知识网站。V0.1 的目标不是发布医学文章，而是建立可复用的静态网站基础、国际化基础设施、SEO 接口、内容合规门禁、质量验证和部署准备，为后续经过真实专业人员审核的内容提供安全边界。

## 目标

- 使用 Astro 静态生成完整 HTML，核心内容不依赖客户端 JavaScript。
- 支持 `th`、`en`、`zh-Hans` 三种语言，URL 前缀分别为 `/th/`、`/en/`、`/zh/`。
- 通过统一、类型安全的模块生成标题、描述、canonical、robots、Open Graph、hreflang、JSON-LD、sitemap 和 robots.txt。
- 以 Astro Content Collections + Zod 建立医学内容模型，并阻止未完成审核的内容进入公开页面、sitemap、结构化数据和构建产物。
- 提供语义 HTML、键盘可用、深色/浅色/系统主题和 reduced-motion 基础支持。
- 提供 Vitest、Playwright、TypeScript、ESLint、Prettier、内容门禁和静态构建验收。
- 提供 Docker、Nginx 和 GitHub Actions 配置，但不部署、不修改 DNS、不接入真实分析或生产凭据。

## 非目标与反目标

- V0.1 不发布正式医学文章，不实现诊断、个性化治疗、剂量计算、购药、处方、医疗咨询、用户账号、数据库、后端 API、CMS、支付或联盟营销。
- 不收集健康记录、疾病、用药、处方、身体指标或其他敏感健康信息。
- 不伪造作者、医学审核人、审核记录、研究数据、监管批准或医疗合作。
- 不通过 IP 强制跳转语言，不生成不存在的翻译页面链接，不使用隐藏文本、关键词堆砌、虚假结构化数据或低质量批量页面。
- 不宣称 Core Web Vitals、搜索排名、收录、流量或医疗效果已经达标；除非有实际测量证据，否则只记录目标值。

## 约束

- 项目技术方向固定为 Astro、TypeScript strict、Tailwind CSS、Markdown/MDX、Astro Content Collections、Zod、pnpm、Vitest、Playwright、ESLint、Prettier、Pagefind、Sharp、Docker、Nginx、GitHub Actions 和 Cloudflare 部署边界。
- 采用当前环境与包仓库可验证的稳定版本；版本写入 `package.json` 和锁文件，以实际安装结果为准。
- 所有代码注释使用中文；文档中的未确定事项使用 TBD、Pending 或 Proposed。
- 只修改项目相关文件，保留已有 `.codegraph/daemon.pid` 等环境生成文件，不提交凭据或私密环境变量。

## 架构方案比较

### 方案 A：Astro 静态生成 + 原生组件 + 本地内容模型（采用）

页面由 Astro 在构建时生成，i18n、SEO、内容状态和发布资格分别由小型 TypeScript 模块负责，主题切换只使用一个受控的原生脚本。优点是符合 SEO、性能、隐私和 V0.1 无后端边界；缺点是内容发布需要重新构建，并且未来需要继续维护内容门禁。

### 方案 B：React/其他 UI 框架作为全站渲染层

可以快速复用组件，但会引入额外客户端 JavaScript、hydration 和可访问性验证成本，违背静态优先及最小依赖约束。V0.1 不采用。

### 方案 C：先接入 CMS、数据库和 API

有利于后续编辑工作流，但超出 V0.1 范围，扩大隐私、部署、安全和合规风险。V0.1 不采用。

## 采用方案的结构

```text
浏览器
  │
  ├─ /                 语言入口，不做 IP 自动跳转
  ├─ /th/ /en/ /zh/    独立静态本地化页面
  ├─ /sitemap.xml      只列出允许索引的已生成页面
  └─ /robots.txt       公开爬取策略与 sitemap 地址

Astro build
  ├─ src/i18n          locale registry、字典、路由和翻译关系
  ├─ src/seo           metadata、canonical、hreflang、JSON-LD
  ├─ src/schemas       内容状态和发布资格 schema
  ├─ src/utils         内容门禁和 URL 辅助函数
  ├─ src/content       V0.1 测试内容，仅 draft/test-only
  └─ scripts            内容、静态产物和 SEO 验证
```

所有三种语言在 V0.1 都提供语言入口、关于页面和安全边界页面，因此这些页面可以生成互 reciprocal hreflang；以后若某个内容只有部分译文，hreflang 只使用真实存在且允许索引的语言集合。`x-default` 指向根语言入口。

页面骨架为：跳过链接 → header/语言切换/主题选择 → main → footer。视觉采用深青色与蓝绿色、浅色为默认、系统偏好可继承，主题选择不会写入服务器或收集用户健康数据。

## 合规门禁

内容 schema 定义 `draft`、`fact-check-pending`、`medical-review-pending`、`compliance-review-pending`、`translation-review-pending`、`approved`、`published`、`archived`。只有 `published`、`public`、有来源、具备实际审核字段的条目才具有公开资格；V0.1 的测试条目明确为 `draft` 和 `test-only`。构建前脚本扫描内容 frontmatter，构建后脚本检查 `dist/`，两者共同阻止不合规内容暴露。

## 验收标准

- `pnpm install --frozen-lockfile` 可完成依赖安装。
- 类型检查、Lint、格式检查、单元测试、集成/静态产物检查、E2E（若浏览器可用）、内容验证和生产构建均有真实命令结果记录。
- 每个公开 HTML 页面有唯一 title、description、canonical、语言属性和可验证的 hreflang；sitemap 和 robots 与公开路由一致。
- `dist/` 不包含 V0.1 测试内容或未审核内容。
- Docker/Nginx/CI 配置存在且不包含生产凭据；部署仍为 Pending。
- 所有未执行或外部依赖的检查在证据文档中明确说明。

## 实现者决定

- 具体包版本以 2026-11-27 当前环境中的 `pnpm view` 和安装锁文件为证据，不把“最新版”当作兼容性证明。
- sitemap 使用项目内类型安全生成器，避免 V0.1 为一个简单静态站点引入额外运行时依赖。
- Pagefind 作为构建后搜索索引工具保留，但 V0.1 不实现面向用户的搜索 UI；这是依赖验证和未来能力准备，不代表搜索功能已交付。
- Cloudflare 仅记录为 DNS/CDN 边界，V0.1 不调用其 API 或写入账号配置。
