# OKOCT Health V0.2 Design System 设计说明

状态：依据 V0.2 需求进入实施；本阶段不授予生产发布、推送或部署授权。

## 意图

V0.2 将 V0.1 的合规静态页面壳升级为具有明确品牌识别度的 Premium Scientific Editorial Website。首要用户是需要以泰语、英语或简体中文阅读一般健康知识的普通读者；在没有真实且完成审核的医学文章前，页面必须诚实呈现站点范围、编辑标准和内容准备状态，而不是用虚构文章、医生或研究数据填充界面。

## 目标

- 建立 Astro 原生、静态优先、低客户端 JavaScript 的设计 token 和组件基础。
- 将首页升级为结构完整的科学编辑型入口：品牌介绍、搜索入口、主题探索、内容准备状态、安全边界、研究标准和编辑标准。
- 保留 V0.1 的语言路由、SEO、内容门禁、Pagefind、主题切换和测试能力。
- 提供可复用的布局、核心组件、品牌 SVG 资产和页面模板，为后续经过真实审核的内容留出稳定接口。
- 在 320–1920px、三种语言、浅色/深色/系统主题、键盘和 reduced-motion 条件下验证布局与可访问性。

## 非目标与反目标

- 不发布未经事实核查、医学审核、合规审核和翻译审核的医学文章。
- 不伪造作者、医学审核者、机构、研究数据、监管批准、用户评价或治疗效果。
- 不增加数据库、CMS、账号、支付、购药、处方、诊断、个性化治疗、剂量建议或敏感健康数据收集。
- 不引入大型 UI 框架、SPA 渲染层、重量级动画、WebGL、Canvas 或外部字体请求。
- 不因视觉重构改变 V0.1 的公开 URL 语义或发布资格。

## 约束

- 继续使用 Astro 7、TypeScript strict、Tailwind CSS 4、原生 Astro 组件、Vitest、Playwright 和 Pagefind。
- 颜色和组件样式通过 CSS Custom Properties 与 Tailwind 主题 token 获取；页面不大量散落硬编码颜色。
- 公开页面只使用真实的站点范围、编辑标准、安全说明和明确空状态文案。
- 视觉目标是 WCAG 2.2 AA 的工程实现；对比度、键盘和真实设备审查必须记录实际证据。
- 所有未执行、跳过或受环境限制的检查必须在 `docs/evidence/V0.2-VERIFICATION.md` 标明。

## 方案比较与采用方案

### 方案 A：Astro 原生的系统先行（采用）

先建立品牌、token、字体、布局、原生组件和主题契约，再把它们组合为首页、搜索页和模板。公开页面仍由 Astro 静态生成，只有主题初始化与搜索结果使用最小脚本。该方案与 V0.1 的架构、SEO 和隐私边界一致，改动可分段验证；代价是需要在 CSS token 和三语言字典上投入更多前置工作。

### 方案 B：先做首页视觉重构，再回填系统

快速修改首页和全局 CSS，之后从页面中抽取组件。这种方式能更早看到视觉结果，但容易把页面专用样式重新散落到组件中，与“先完成设计决策再实现组件”的要求冲突，也增加多语言和主题回归风险，因此不采用。

### 方案 C：引入 React 或第三方 headless UI 框架

可获得更多现成交互，但会增加依赖、hydration、bundle 和无障碍审查范围，并与静态优先、最小 JavaScript 的架构原则冲突，因此不采用。

## 视觉方向

品牌概念为“Evidence Horizon”：把健康知识表现为可逐层阅读的证据地平线，而不是医疗机构或药品品牌。页面以深蓝绿色墨色承载正文，冷静的 jade signal 表示可操作的导航与状态，amber evidence 只用于来源/状态提示；首页英雄区使用带轴线、刻度和柔和光晕的轻量 SVG/CSS 抽象图形，形成唯一强记忆点，其余界面保持克制的边框、留白和清晰层级。

### 色彩

| 语义      | 浅色      | 深色      | 用途               |
| --------- | --------- | --------- | ------------------ |
| ink       | `#0b252b` | `#e8f3f1` | 正文和标题         |
| ink-muted | `#49666a` | `#a7c5c2` | 辅助说明           |
| canvas    | `#f2f7f5` | `#0b171b` | 页面背景           |
| surface   | `#ffffff` | `#13282d` | 内容表面           |
| signal    | `#147d78` | `#6ed7c5` | 链接、行动和焦点   |
| evidence  | `#b48639` | `#e2bd6b` | 证据状态和少量强调 |

### 字体与排版

使用本地可用的系统回退栈，优先匹配 Thai 与简体中文字符覆盖：`Noto Sans Thai`、`Noto Sans SC`、`Tahoma`、`ui-sans-serif`。标题采用同一无衬线家族的紧凑字重形成现代科学感；正文使用 68ch 左右的阅读宽度、较松行高和自然换行。文案使用 sentence case，不依赖全大写 eyebrow 或装饰性标签表达层级。

大屏使用宽容器和不完全对称的 5/7 网格；移动端改为单列，英雄图形位于文案之后，正文和行动始终左对齐。卡片只在具有清晰信息边界时使用，避免所有模块都变成相同圆角 SaaS 卡。

## 组件与行为决策

- 原子层：`Container`、`Stack`、`Button`、`Link`、`Badge`、`Divider`、`Icon`。
- 内容层：`SectionHeading`、`Card`、`TopicCard`、`ArticleCard`、`FeaturedContent`、`ContentGrid`、`EmptyState`。
- 安全层：`MedicalDisclaimer`、`SafetyNotice`、`EvidenceNote`、`AuthorCard`、`ReviewerCard`；在没有真实人员记录时不渲染虚构身份。
- 导航层：`SiteHeader`、`SiteFooter`、`Breadcrumbs`、`LanguageSwitcher`、`ThemeControl`、`SearchTrigger`、`SearchDialog`。
- 阅读/模板层：`PageLayout`、`ArticleLayout`、`TopicLayout`、`LegalLayout`、`ErrorLayout`；它们复用 `BaseLayout` 的 SEO，不复制 head 逻辑。
- 所有适用的交互组件提供 default、hover、focus、active、disabled、loading、empty 或 error 状态；不适用状态不伪造。

## SEO、内容和国际化

V0.2 继续由 `buildSeoMetadata()` 统一生成 metadata、canonical、alternate links 和 JSON-LD。新增搜索页面使用 `noindex,nofollow`，不进入 sitemap；首页、关于和安全页保留公开集合。三种语言的界面文案分别维护，缺失翻译不生成链接。首页的“GLP-1”区块只表达未来知识主题的准备状态，不输出医学结论、疗效或购买引导。

## 验收标准

- 设计文档、token、品牌 SVG、组件和页面模板存在并由项目约定引用。
- 首页在三种语言和三种主题下生成稳定静态 HTML，公开内容不含未审核测试文章。
- `typecheck`、lint、格式、内容门禁、单元测试、集成测试、生产构建、SEO 验证和 E2E 均有本次运行记录。
- Playwright 实际生成并检查桌面、移动、中文/泰文、浅色/深色截图；截图中无横向溢出、重叠或文字裁切。
- Docker 构建若 daemon 仍不可用则保持 BLOCKED，不将其写成通过。

## 实施者决定

- 采用当前分支内的原生实现，不创建额外 worktree；用户已明确要求在当前仓库完成实施，分支名为 `codex/okoct-v0.2-design-system`，不推送。
- 为保持页面真实，所有没有可验证来源的内容模块使用站点介绍或空状态；不会用测试文章作为展示数据。
- 采用内联 SVG/本地 CSS 视觉资产，避免网络字体、第三方图片和版权不明素材。
