# OKOCT Health V0.2.1 Visual Refinement 设计说明

状态：待批准；本阶段不授予生产发布、远程推送或部署授权。

## 意图

V0.2.1 针对 V0.2 验收评审中的视觉和质量问题做一次受控的体验优化，把首页从“设计精致的项目介绍页”推进到更清晰的 Premium Scientific Editorial 入口。目标用户仍是希望以泰语、英语或简体中文阅读一般健康知识的普通读者。由于当前没有经过完整事实核查、医学审核、合规审核和翻译审核的正式文章，本次优化必须让页面更容易理解，而不能用虚构文章、研究数据、专家身份或审核状态填充页面。

本阶段建立在现有 Astro 静态架构、设计 token、SEO 契约、内容发布门禁和原生组件上，重点解决首页内容密度、移动端导航、信息层级、间距和可测量质量。

## 目标

- 让首页首屏明确表达 OKOCT 的知识方向：体重管理、GLP-1、减重针、用药安全和泰国相关背景，同时清楚说明正式内容尚未发布。
- 将首页文章、研究和主题内容区块改为内容驱动；没有可发布内容时隐藏对应列表或准备状态区块，只保留真实的站点范围、安全边界和编辑原则。
- 将移动端 Header 收敛为单行工具栏，并提供可键盘操作、可 Escape 关闭、可恢复焦点的完整菜单。
- 优化 Hero、Evidence Horizon、Typography、Section Spacing 和按钮状态，同时保留现有品牌视觉语言、浅色/深色/系统主题和 reduced-motion 支持。
- 使用自动化 axe 检查、生产预览截图、Lighthouse 实验室基线和 Docker 验证补齐 V0.2 验收证据。
- 更新 V0.2.1 设计、任务、验证和变更记录，但不提前进入 V0.3 Content Engine。

## 非目标与反目标

- 不发布正式医学文章，也不把规划主题写成已有文章、研究集合或审核资源。
- 不伪造作者、医学审核者、机构、研究数据、监管批准、用户评价、治疗效果或 Google 收录结果。
- 不创建不存在的主题页面或导航链接；当前导航只链接已经存在的首页、关于、安全和搜索页面。
- 不改变公开 URL、canonical、hreflang、sitemap、robots、Pagefind 内容门禁或 noindex 搜索约束。
- 不引入数据库、CMS、账号、支付、购药、处方、诊断、个性化治疗、剂量建议或敏感健康数据收集。
- 不引入 React、重量级动画、WebGL、Canvas、外部字体或不必要的运行时脚本。
- 不在本阶段部署生产环境、推送远程仓库或修改生产基础设施。

## 约束

- 继续使用 Astro 7、TypeScript strict、Tailwind CSS 4、原生 Astro 组件、Vitest、Playwright 和 Pagefind。
- 所有 UI 文案继续进入 `src/i18n/dictionaries.ts`，并为 `th`、`en`、`zh-Hans` 分别维护；不得把默认语言文案复制到缺失翻译。
- 所有公开内容继续遵守 `published`、`public`、`indexable`、来源、作者、事实核查、医学审核、合规审核、翻译审核和发布日期门禁。
- 视觉实现继续使用 `src/styles/global.css` 的语义 token；组件不散落主题无关的原始颜色。
- 目标是 WCAG 2.2 AA 的工程实现。自动化工具通过不等同于完整合规声明，实际限制必须记录。
- 实验室性能数据与真实用户数据分开记录；不得把 TBT 当作 INP，也不得在没有测量时宣称 Core Web Vitals 达标。

## 方案比较与采用方案

### 方案 1：渐进式现有组件优化（采用）

保留当前页面、SEO 和内容模型边界，在 `SiteHeader`、首页组合、Hero、空状态和全局 token 上做小范围重构；新增一个原生移动菜单交互，并用现有 `getPublicContent()` 结果控制内容区块。将 axe 和生产预览验证加入验收流程。该方案改动集中、回归面最小，并且能为 V0.3 的真实内容接入留下清晰边界。

### 方案 2：首页与导航整体重构

重新设计首页区块模型和导航状态层，再迁移现有组件。它对未来内容引擎更规整，但会扩大本次改动的结构和回归风险，不符合“只做一次针对性优化”的范围。

### 方案 3：仅做 CSS 与文案微调

可以快速改善截图，但不能解决移动端菜单、内容驱动渲染、Escape/焦点管理和自动化无障碍验收，因此不能满足本次 P0 验收项。

## 设计决策

### 1. 首页信息架构

首页继续保持以下真实信息顺序：Global Header → Hero → Knowledge Search → Topic Scope → 可发布内容（有数据才显示）→ Safety Boundary → Editorial Standards → Global Footer。

Topic Scope 可以展示规划中的知识方向，但它是站点范围说明，不是可点击的无内容专题页。Featured、Research 和 GLP-1 文章列表都由内容集合中的可发布条目决定；当当前集合没有可发布条目时，这些文章/研究区块不渲染。搜索入口仍保留，因为它是已存在的 noindex 功能页面，但搜索页只显示一个诚实的空状态。

内容判断复用现有 `isPublishableContent()` / `getPublicContent()` 规则，并按当前 locale 过滤；不复制一套放宽条件的首页判断逻辑。当前 schema 没有 topic/category 字段，因此 V0.2.1 只为通用 Featured 内容预留“有对应 locale 的可发布条目才显示”的接口；GLP-1、Research 等专题分类与列表映射留给 V0.3 Content Engine，不在本阶段猜测字段或伪造专题数据。

### 2. Hero 与 Evidence Horizon

Hero 的标题和副标题要直接表达体重管理相关知识方向，同时使用“正在建立/准备发布/未来内容须经审核”等准确表述，不暗示当前已经拥有审核文章。所有三语言文本都由 dictionary 提供。

Evidence Horizon 保留为唯一强装饰：继续使用内联 SVG、网格、圆弧、轴线和证据色；增加层次和品牌关联，但不加入临床数据、坐标数值、研究结论或会被理解为真实实验图表的统计标记。移动端缩小图形高度，减少首屏占用；`prefers-reduced-motion: reduce` 下不播放非必要动画。

### 3. 移动端 Header

桌面端保留简洁横向导航。移动端使用单行工具栏：Logo、搜索、语言、菜单；主题控件进入菜单面板。

菜单采用浏览器原生 `<details>/<summary>` disclosure 和小型增强脚本，不引入交互框架。`<details>` 是无脚本时的可用基线；脚本只负责同步 `aria-expanded`、打开后把焦点移到菜单首项、响应 Escape 关闭并将焦点还给触发器、以及菜单打开期间的背景滚动控制。触发器必须提供本地化 accessible name 和 `aria-controls`；菜单中的链接只来自当前真实路由集合。

无脚本时页面仍保持可读并保留当前真实导航链接；不能因为菜单脚本失败而隐藏所有站点导航。

### 4. 间距、Typography 与状态

减少首页的统一大间距，按区块信息密度使用以下目标：

| Token      | Desktop | Mobile |
| ---------- | ------- | ------ |
| Section XS | 24px    | 16px   |
| Section SM | 40px    | 24px   |
| Section MD | 64px    | 40px   |
| Section LG | 96px    | 56px   |
| Section XL | 128px   | 72px   |

实际实现继续通过 token 和现有 Tailwind 主题表达，不用固定高度裁切多语言文本。英文标题控制在可读行长，泰文保留足够行高，简体中文不依赖强制断词。主要按钮、次要按钮、disabled、focus、loading（适用时）和错误状态分别保持可辨识的文字与对比度。

### 5. 验证与证据

本阶段至少记录：

- `pnpm typecheck`、lint、format、内容门禁、unit、integration、build、SEO 和 E2E 的实际结果。
- `@axe-core/playwright` 对三语言首页、搜索页和打开菜单状态的实际结果；只报告工具覆盖到的规则。
- 生产构建预览下的英文桌面浅/深色、泰文首页、中文移动端浅/深色、移动菜单、搜索页截图；不使用 Astro 开发工具栏。
- Lighthouse 的实验室结果，包括 Performance、Accessibility、Best Practices、SEO、LCP、CLS、TBT、JavaScript 和 CSS 传输大小；不把这些结果写成真实用户体验数据。
- Docker 镜像构建、容器启动、Nginx HTTP、静态资源、安全响应头、404、sitemap 和 robots 验证。
- 未执行、跳过、工具限制以及医学/法律/隐私仍 Pending 的事项。

## 验收标准

- 三语言首页首屏准确表达站点范围和当前内容状态，不虚构已审核内容。
- 无可发布文章时，首页不显示 Featured、Research 或 GLP-1 的重复空状态区块；真实站点介绍、安全边界和编辑标准仍可访问。
- 移动端菜单满足本地化 accessible name、键盘操作、Escape 关闭、焦点恢复、背景滚动控制和真实路由约束。
- 320、375、390、768、1024、1280、1440、1920px 下无横向溢出、重叠或文字裁切；浅色、深色、系统主题和 reduced-motion 内容可用。
- 现有 canonical、hreflang、JSON-LD、sitemap、robots、Pagefind 和 draft/test-only 隔离不回归。
- Docker 已构建并完成容器级静态站点验证；Lighthouse、axe 和截图都有实际记录。
- `docs/evidence/V0.2.1-VERIFICATION.md`、`CHANGELOG.md`、README、设计/路线图/任务状态文档与实际结果一致。

## 已知限制

- 当前没有正式医学文章，因此内容区块的“自动展示已发布文章”只能通过无数据路径和测试隔离数据验证，不能证明医学审核流程本身已经完成。
- axe 只能覆盖自动化规则，不能替代真实设备、屏幕阅读器、专业翻译、医学审核或法律意见。
- Lighthouse 是实验室基线；真实用户 LCP、INP、CLS、Google 收录、排名和生产网络行为仍需后续单独测量。
- Docker 镜像构建和本地容器运行不等于生产 TLS、Cloudflare、VPS、密钥和发布授权审查。
