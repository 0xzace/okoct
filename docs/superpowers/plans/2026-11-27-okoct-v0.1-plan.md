# OKOCT Health V0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the V0.1 static, multilingual, SEO-first and compliance-gated foundation for OKOCT Health without publishing formal medical content.

**Architecture:** Use Astro static generation with native `.astro` components, Tailwind CSS through the official Vite plugin, typed locale/route/SEO modules, and an Astro Content Collection validated with Zod. Build-time and post-build scripts enforce content publication eligibility and inspect the generated static output.

**Tech Stack:** Astro 7.4.13, TypeScript 6.0.3, Tailwind CSS 4.3.5, `@tailwindcss/vite` 4.3.5, Zod 4.6.7, Vitest 5.1.2, Playwright 1.65.1, ESLint 10.15.0, Prettier 3.10.1, Pagefind 1.6.0, Sharp 0.35.5, pnpm 10.24.0, Docker, Nginx and GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-27-okoct-v0.1-design.md`

## Global Constraints

- Product is an independent, non-commercial health knowledge website for Thailand.
- V0.1 does not publish formal medical articles; test content must remain clearly marked and excluded from production output.
- Supported locales are `th`, `en`, and `zh-Hans`; URL prefixes are `/th/`, `/en/`, and `/zh/`; default locale is `th`.
- Use static generation, semantic HTML, strict TypeScript and minimal client-side JavaScript.
- Do not add a database, backend service, queue, CMS, user account system, commerce, diagnosis, treatment or dosage feature.
- Do not commit credentials, private keys, private environment variables or production deployment changes.
- All code comments must be written in Chinese.
- Never claim performance, medical, indexing, deployment or compliance outcomes without executed evidence.

## Review Focus

- A route with a missing translation must not emit a nonexistent language link; test in Task 2 with a partial locale map.
- A draft or unreviewed content entry must not become an HTML page, sitemap URL, structured-data item or build artifact; test in Task 3 and Task 5.
- Canonicals, hreflang and `x-default` must remain absolute and reciprocal for the three localized pages; test in Task 2 and Task 5.
- Theme switching must preserve semantic HTML, keyboard access and reduced-motion behavior without requiring client rendering for page content; test in Task 4.
- Invalid external URL/config input must not create malformed canonical or sitemap output; test in Task 2 and Task 5.
