# OKOCT Health V0.2.1 Visual Refinement Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Improve the V0.2 homepage and mobile navigation without changing OKOCT Health's static architecture, medical-safety boundary, SEO contracts, or publication gate.

**Architecture:** Keep Astro static generation and the existing semantic component system. Add a pure publication-filter helper for the homepage, use a native `<details>/<summary>` mobile disclosure enhanced with a small script, and keep all user-facing copy in the three locale dictionaries. Run E2E against a production preview so visual evidence excludes the Astro dev toolbar.

**Tech Stack:** Astro 7, TypeScript strict, Tailwind CSS 4, CSS custom-property tokens, Vitest, Playwright, `@axe-core/playwright`, Pagefind, Lighthouse, Docker/Nginx.

**Spec:** `docs/superpowers/specs/2026-11-27-okoct-v0.2.1-visual-refinement-design.md`

## Global Constraints

- Continue using Astro 7, TypeScript strict, Tailwind CSS 4, native Astro components, Vitest, Playwright and Pagefind.
- All UI copy remains in `src/i18n/dictionaries.ts` and is maintained separately for `th`, `en`, and `zh-Hans`.
- Public content must continue to satisfy the `published`, `public`, `indexable`, source, author, fact-check, medical-review, compliance-review, translation-review, and publication-date gates.
- Visual implementation continues to use semantic tokens from `src/styles/global.css`; components must not scatter theme-independent raw colors.
- WCAG 2.2 AA is the engineering target; automated results do not constitute a complete compliance declaration.
- Laboratory performance data and real-user data remain separate; TBT must not be reported as INP.
- Do not add article routes, topic/category fields, databases, CMS, accounts, payments, medical commerce, diagnosis, personalized treatment, dosage advice, or sensitive health-data collection.
- Do not push, deploy, or modify production infrastructure.

## Review Focus

- **Unpublished content input:** draft/test-only entries must not render in any homepage content block; cover in `tests/unit/home-content.test.ts` and generated-output assertions.
- **Locale mismatch:** a published entry for another locale must not appear on the current locale homepage; cover in `tests/unit/home-content.test.ts`.
- **Mobile menu state:** opening, Escape closing, focus restoration, and background-scroll behavior must remain synchronized; cover in `tests/e2e/mobile-menu.spec.ts`.
- **No-JavaScript baseline:** the native disclosure must remain operable without the enhancement script; cover with semantic markup assertions and manual evidence in the verification record.
- **Theme and responsive states:** duplicated desktop/mobile controls and all required viewport widths must not create overflow or lose theme persistence; cover in `tests/e2e/v0-2-1-visual.spec.ts` and existing theme E2E coverage.
