# OKOCT Health V0.4 Technical SEO Engine Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Build a local, fail-closed Technical SEO audit pipeline for the Astro production output, with crawl analysis, SEO rules, reports, regression comparison, quality gates, CLI commands, CI integration, and recorded verification evidence.

**Architecture:** Keep the existing Astro/content publication path as the source of truth. Add a dependency-free ESM SEO engine under `scripts/seo/` that crawls `dist/` or an explicitly supplied local HTTP origin, produces normalized page snapshots, runs focused analyzers, and writes machine-readable and human-readable reports. Keep synthetic article fixtures outside the production build and make the quality gate block content leakage and critical/error findings by default.

**Tech Stack:** Astro, TypeScript/Vitest for existing application code and tests, Node.js ESM scripts, built-in `fs`, `url`, and `fetch`, Playwright/Lighthouse only for explicitly run laboratory checks.

**Spec:** User-provided V0.4 Technical SEO Engine request in the attached review text; project constraints in `AGENTS.md`.

## Global Constraints

- Preserve the V0.3 Content Engine and fail-closed Publication Gate.
- Do not publish or expose unreviewed medical content, synthetic article fixtures, or editorial/SEO-lab records.
- Do not fabricate rankings, Search Console data, Core Web Vitals, authors, reviewers, sources, or structured-data entities.
- Use `th`, `en`, and `zh-Hans` with URL prefixes `/th/`, `/en/`, and `/zh/`; only real indexable translations may participate in hreflang.
- Keep the default SEO quality gate blocking for leakage, invalid canonical, sitemap leakage, hreflang leakage, redirect loops, broken critical links, and Critical/Error issues.
- Do not add a database, CMS, user account system, medical commerce, or production deployment change.
- All code comments added by this plan are Chinese.

## Review Focus

- A draft or synthetic article fixture in the workspace must never appear in `dist/`, sitemap, Pagefind, or reports marked as public; test in the fixture/leakage task.
- An HTML page with malformed or cross-origin canonical must be reported as an Error and block the gate; test in canonical/indexability rules.
- A hreflang target that is missing, duplicated, non-indexable, or non-reciprocal must be reported without inventing a translation; test in hreflang rules.
- A redirect chain or loop must be reported, while a normal 404/410 must not be converted to a homepage redirect; test in redirect analysis.
- Performance lab output must be labeled as laboratory evidence and unavailable metrics must remain Pending rather than being treated as passed field data; test in performance/reporting.
