# OKOCT Health V0.3 Content Engine Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 在不引入数据库或 CMS 的前提下，建立基于 Astro Content Collections、Zod、Markdown/MDX 和 Git 的可追溯内容生产、审核、发布和审计链路。

**Architecture:** 保留现有 Astro 静态站点和 Design System，将内容实体与非公开 editorial 记录放在构建时可验证的仓库中。生产页面、sitemap、Pagefind、JSON-LD、hreflang 和首页只通过统一 repository/publication gate 读取有效的 `published` 内容；审核记录绑定文章 revision 和 content hash，内容变化自动使旧审核失效。关键词、主题、brief、reference 和 audit 以 YAML/Markdown 文件进入 Git，但不复制 editorial 私密证据到 `dist/`。

**Tech Stack:** Astro 7 Content Collections, `astro:content`, Zod 4, TypeScript strict, Markdown/MDX, Pagefind, Vitest, Playwright, Node.js ESM CLI。

## Global Constraints

- 初期继续使用 Git + Markdown/MDX + Astro Content Collections，不引入数据库或独立 CMS。
- 公开内容必须是经过真实事实核查、医学审核、合规审核和翻译审核的已批准版本；自动化验证不能替代专业审核。
- 未发布内容不得进入 HTML、sitemap、RSS、Pagefind、JSON-LD、hreflang、相关内容、首页或生产构建产物。
- 未知关键词搜索量、竞争难度和 CPC 必须保持 `null`，不得以 AI 估计值代替真实研究数据。
- 不伪造医学事实、参考文献、作者、审核人员、审核记录、监管批准、搜索数据或临床研究。
- 支持 `th`、`en`、`zh-Hans`，URL 前缀保持 `/th/`、`/en/`、`/zh/`，不生成不存在的翻译链接。
- 不引入购药、处方、诊断、个性化治疗、剂量建议、药品推广、账号或敏感健康数据收集能力。
- 不提前实施 V0.4 Technical SEO；不推送、部署、修改生产基础设施或删除用户改动。
- 所有新增代码注释使用中文；优先复用现有组件和工具。

## Review Focus

- `published` 但缺少真实审核记录、版本或 hash：应被 fail-closed gate 拒绝；由 Task 4 的 publication tests 覆盖。
- 已审核文章正文或关键引用改变：旧审核不能继续有效；由 Task 3 的 review invalidation tests 覆盖。
- 未发布翻译、撤回文章和未审核草稿：不能进入 hreflang、sitemap、Pagefind、related links 或 dist；由 Task 6/7 的 leakage tests 覆盖。
- 关键词和关系实体引用不存在、locale 不匹配或重复 slug/title：应报告确定性错误而不是静默跳过；由 Task 2/5 的 relationship tests 覆盖。
- 参考资料 URL 可访问但医学内容仍未被专业人员核验：技术校验不能把它提升为 verified；由 Task 5 的 reference/audit tests 覆盖。
